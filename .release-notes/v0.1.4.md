## TELOS SDK v0.1.4 — 2026-05-27

Codex (`wire_api = "responses"`) is now a first-class harness on the gateway.

### Fixed

- **Codex.app with ChatGPT login could not reach the gateway** ([init/codex.py](init/codex.py)): the installer assumed an `OPENAI_API_KEY` provider, so it pointed Codex's custom `base_url` at `/upstreams/openai/v1` → `api.openai.com/v1/responses`. Codex.app users (the common case) authenticate with a ChatGPT JWT, which `api.openai.com` rejects (`403 "Missing scopes: api.model.read"`). The installer now reads `~/.codex/auth.json` and, when `auth_mode = "chatgpt"`, routes through a new `codex-chatgpt` upstream pointing at `https://chatgpt.com/backend-api/codex` (no `/v1` prefix). API-key mode is unchanged.

### Added

- **Dashboard shows Codex traffic.** The Responses-API endpoint (`POST .../responses`) is no longer a silent passthrough on the gateway: it parses the terminal `response.completed` SSE event, normalizes the usage block (`input_tokens` − `input_tokens_details.cached_tokens` → raw / cache_read / cache_write / output), and writes a `usage.jsonl` row tagged with the slug's `via` (`codex`). [registry.py](registry.py) adds the `codex` → "Codex" display name so the dashboard's "Breakdown by harness" table picks it up.
- New tests: `_test_openai_responses_logs_usage` ([tests/test_proxy_openai_route.py](tests/test_proxy_openai_route.py)), `test_detect_auth_mode` and `test_install_chatgpt_mode_routes_to_backend_codex` ([tests/test_init_codex.py](tests/test_init_codex.py)).
