## 核心数据结构 — TelosIR

所有 dataclass 都是 **frozen（不可变）**：bridge 的"修改"返回一个新 IR，而非原地改字节。

```python
@dataclass(frozen=True)
class TelosBlock:
    id: str
    band: Band                  # PIN / FOLD / DROP
    kind: BlockKind             # text / tool_def / tool_use / tool_result / image / thinking
    payload: Any                # 引擎无关内容；emit 时由适配器翻译
    ref_slug: str | None        # 非空 → 来自 ref-pool
    source_tag: str | None      # 诊断：哪条 harness 规则分的带
    extra: Mapping              # 引擎所需的稳定旁路信息（image detail、tool source…）

@dataclass(frozen=True)
class TelosMessage:
    role: Literal["system", "user", "assistant"]
    blocks: tuple[TelosBlock, ...]      # 必须满足 §5：pin* → fold* → drop*

@dataclass(frozen=True)
class TelosIR:
    session_id: str
    tools:    tuple[TelosBlock, ...]    # 全部 band=PIN
    system:   tuple[TelosBlock, ...]    # pin* → fold*（含 ref-pool）→ drop*
    messages: tuple[TelosMessage, ...]
    ref_pool: Mapping[str, TelosBlock]  # slug → block
    hints:    TelosHints
```

### UsageReport — 归一化 usage

```python
@dataclass(frozen=True)
class UsageReport:
    raw_input:   int   # 既未命中也未写入缓存的输入 token
    cache_read:  int   # 从缓存读取
    cache_write: int   # 本次请求新写入缓存的 token
    output:      int
    raw: Mapping       # 原始 usage 字段，留作诊断
```

## Bridge — 五个原语

每会话一个实例，**有状态**。

| 原语 | 方法 | 效果 |
|---|---|---|
| **Place** | `place(segment, blocks)` / `append_message(msg)` | 替换一段的块 / 追加一条消息，立即跑 §5 检查 |
| **Pin** | `pin(slug, payload)` | 注册一个 ref-pool 条目；slug 立即冻结（注册的是 `band=FOLD` 条目——这里的 "Pin" 指*固定指针*，而非 `band=PIN`）|
| **Mark** | `mark()` | 委托引擎适配器决定缓存锚点位置（返回 `EmitPlan`）|
| **Fold** | `fold(slugs=, message_range=, summary=)` | 折叠一个 ref-pool 条目（只换 payload，不换 slug）或把历史折成摘要 |
| **Refresh** | `refresh(plan)` | 触发引擎续约；自适应门控 |

### 规范化（修复 R5）

统一在 emit 前完成。根因：Swift / Go 的 JSON 序列化随机化键序，导致 prefix-hash 漂移。

- `_canonicalize_payload` —— 递归地按字典序排序 dict 键。
- `_canonicalize_schema` —— 对 JSON-Schema 子树，额外排序**集合语义数组**（当前仅 `required`）；刻意
  **不**排序 `enum` / `examples` / `anyOf` / `oneOf` / `allOf`（顺序有语义）。
- `_canonicalize_tool_def` —— 识别 Anthropic（`input_schema`）与 OpenAI（`function.parameters`）两种工具形态。
- `_tool_sort_key` —— 稳定的工具数组排序键 `(source_rank, mcp_server, name)`；`source_rank`：builtin(0) →
  mcp(1) → user(2) → unmarked(3)。

<Warning>
  `tool_use` / `tool_result` 的 payload 是**用户数据**；只排序键——绝不动数组顺序（payload 中恰好叫
  `required` 的字段不得被悄悄重排）。
</Warning>

### 双向操作（仅 vLLM / SGLang）

`is_bidirectional = isinstance(engine, BidirectionalEngineAdapter)`。

| Bridge 方法 | 闭源 API | vLLM / SGLang |
|---|---|---|
| `probe_cache()` | `ProbeResult(hit=False)` | 实际发送一次查找 |
| `cooperative_fold(...)` | 等价于 `fold()` + `{}` | 客户端折叠 + 服务端 `evict_span` / `fork_and_replace` 片段 |
| `emit_with_extras(extras)` | 把片段并入 `plan.extras` 再 emit | 同左 |

## 引擎策略

- **Anthropic** —— 唯一支持显式断点。`plan_marks` 产出至多 4 个槽位（**BP-T** tools 末、**BP-S** system
  最后 PIN、**BP-R** system 最后 FOLD、**BP-X** 最近消息最后非 DROP 块、**BP-mid** 当 messages ≥ 19）。超 4
  → 按优先级 `BP-T < BP-S < BP-R < BP-mid < BP-X` 裁剪。`_LOOKBACK=20`，`_MID_ANCHOR_STRIDE=19`。
- **OpenAI** —— 无显式 BP。产出 `routing_key`（`telos-<sha256[:16]>`）+ retention；把块排为 非 DROP → DROP，
  使自动前缀匹配命中。`cache_write` 恒为 0。
- **DeepSeek** —— 零控制面；磁盘上下文缓存始终开启。空 `EmitPlan()`；只靠 非 DROP → DROP 排序。
- **vLLM** —— 双向。写 `cache_policy`（`pin_prefix_until_block` / `evict_span`）+ `cache_salt`。
- **SGLang** —— vLLM 的严格超集。写 `cache_control`（`lock_radix_path` / `path_hash` / `prefer_tier` /
  `affinity_key` / `fork_from_path` / `replace_suffix`）；增加 `fork_and_replace` 与 `tier_hint`（HiCache
  GPU/CPU/disk）。

### usage 解析

| 引擎 | cache_read 字段 | cache_write 字段 |
|---|---|---|
| Anthropic | `cache_read_input_tokens` | `cache_creation_input_tokens` |
| OpenAI | `prompt_tokens_details.cached_tokens` | 恒为 0 |
| DeepSeek | `prompt_cache_hit_tokens` | 恒为 0 |
| vLLM / SGLang | `cached_tokens` | 恒为 0 |

## 不变量与设计约束

| ID | 约束 | 实现 |
|---|---|---|
| §5 | 每段内 `pin* → fold* → drop*` | `assert_band_order`，emit 前后各校验一次 |
| I3 | ref-pool slug 注册即冻结 | `RefPool.register` 重复即抛错 |
| §4 | `[ref:slug]` 引用必须在 ref-pool 中存在 | `lint_blocks` emit 前 fail-fast |
| R2 | 长对话需要中段滚动锚 | Anthropic `BP-mid`（messages ≥ 19）|
| R5 | 跨语言 JSON 键序错乱破坏 cache | bridge 中的 `_canonicalize_*` |
| R6 | thinking 块不能直接附 cache_control | harness 分为 FOLD；引擎 emit 时不附 |
| R7 | BP 超 4 时按优先级截断 | Anthropic `BP-T<BP-S<BP-R<BP-mid<BP-X` |
| R8 | 续约低活跃会话会亏钱 | `refresh` 自适应门控，`REFRESH_THRESHOLD=11` |

## 扩展点

| 你想做什么 | 改哪里 |
|---|---|
| 新增 agent 安装器 | 在 `init/` 加 `<name>.py` 实现 `AgentInstaller`，注册到 `init.INSTALLERS` |
| 新增 harness | 在 `harness/` 加插件，注册到 `registry.py` |
| 新增引擎适配器 | 在 `engine/` 加 `EngineAdapter` / `BidirectionalEngineAdapter` 子类，注册到 registry |
| 新增工具过滤规则 | `output_filter/filters.py` 的 `FallbackFilter`，或经 `rtk` 二进制 |
| 新增 `/v1/chat/completions` 代理路径 | 在 `proxy/server.py` 加路由，复用 OpenAI 流水线 |
| 持久化会话状态 | `BridgeSessionState` 是普通 dataclass，可 JSON 序列化；把 `_SessionRegistry` 改为外部存储 |
| 调整规范化排序 | bridge 的 `_SCHEMA_SET_ARRAY_KEYS`、`_TOOL_SOURCE_RANK` 是模块级名，可 monkey-patch |
