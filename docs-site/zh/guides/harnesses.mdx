harness 是上游 agent 运行时。TELOS 首发支持四个，并且采用适配器驱动，可在不重写 agent 逻辑的前提下增加更多。

## 支持的 harness

| Harness | 典型用途 | `telos init` 自动接入 | 状态 |
|---|---|:---:|:---:|
| Claude Code | Anthropic 原生编码 agent 工作流 | ✅ | 🟢 一等公民 |
| OpenClaw | 集成 TELOS 解析器的开源 agent 运行时 | ✅ | 🟢 一等公民 |
| Hermes | 独立子 IR 处理的多 agent 编排 | ✅ | 🟢 一等公民 |
| Codex | 经本地网关注入的 OpenAI 风格编码工作流 | ✅ | 🟢 支持 |

## 各自如何接入

<Tabs>
  <Tab title="Claude Code">
    `telos init --harness claude-code` 把 `ANTHROPIC_BASE_URL` 写入 `~/.claude/settings.json` 的 `env`
    字段（原子写，备份到 `.telos.bak`，以 `__telos_installed` 标记）。经受住 `npm update`，绝不碰 PATH
    或 npm 包。
  </Tab>
  <Tab title="Codex">
    `telos init --harness codex` 向 `~/.codex/config.toml` 添加 `model_provider = "telos"` 自定义提供方，
    指向 `http://127.0.0.1:7171/upstreams/openai/v1`。OpenAI Responses API 路径作透传；ChatCompletions
    兼容流量被 TELOS 处理。
  </Tab>
  <Tab title="OpenClaw / Hermes">
    `telos init` 各自修补其 provider 配置以指向本地网关。
  </Tab>
  <Tab title="Generic">
    `telos init --harness generic` 为任何尊重 `ANTHROPIC_BASE_URL` 或 `OPENAI_BASE_URL` 的客户端打印手动
    export 指令。
  </Tab>
</Tabs>

## harness 如何被解析

每个 harness 插件是无状态的 `parse(raw) → TelosIR`。它们在 wire 形态与身份上有别：

| | OpenClaw | Hermes | Telos |
|---|---|---|---|
| Wire 形态 | Anthropic `/v1/messages` | Anthropic `/v1/messages` | OpenAI ChatCompletions |
| 工具分类 | `_classify_anthropic_tool`（类型前缀 + server 字段 + 元数据）| 复用 `_classify_anthropic_tool` | `_classify_openai_tool`（仅元数据）|
| `<file>` 入 ref-pool | 否（整个超大 system 项 → slug `system-doc-{i}`）| 是（`<file path=…>`，点号 slug）| 是（短横线 slug）|
| `thinking` 块 | 不处理 | FOLD `kind=thinking` | 不适用 |
| `tool_result` 来源 | 内嵌于 user 消息 | 内嵌于 user 消息 | 独立 `role=tool` → 包进 user 消息 |
| system 提取 | `system` 字段 | `system` 字段 | `messages[]` 开头连续的 `role=system` |
| `source_tag` 前缀 | `openclaw/*` | `hermes/*` | `telos/*` |

工具分类把 `source`（builtin / mcp / user）写入 `TelosBlock.extra`，喂给 bridge 的 `_tool_sort_key`，在
多 MCP 启动竞态中保护 PIN 前缀稳定。

## harness 探测（`_detect_harness`）

对 Anthropic 形态流量，TELOS 在 `hermes` 与 `openclaw` 之间选择。探测按顺序进行，命中即返回：

<Steps>
  <Step title="HTTP 头指纹">
    `User-Agent` 含 `claude-cli`，或 `x-app: cli` → `hermes`。只有代理路径能看到请求头。这可靠地捕捉
    Claude Code 无工具的 Haiku 辅助请求（标题生成 / 话题检测），下面 1–3 步都会漏掉它们。
  </Step>
  <Step title="Envelope 标记">
    在 system 文本**以及**每个 user 文本块中跑成对开闭正则（`system-reminder` / `command-message` /
    `command-name`）→ `hermes`。成对匹配避免把仅在散文中讨论标签的用户误判。
  </Step>
  <Step title="thinking 块">
    任何含 `thinking` 内容块的 assistant 消息 → `hermes`。
  </Step>
  <Step title="工具指纹">
    工具名与 `{Bash, Edit, Read, Write, Grep, Glob, TodoWrite, Task, WebFetch, WebSearch,
    NotebookEdit}` 的交集 ≥ 3 → `hermes`。捕捉 reminder 注入前的首轮请求。
  </Step>
  <Step title="兜底">
    否则 → `openclaw`。
  </Step>
</Steps>

<Note>
  探测是**粘性**的。代理按客户端记住可信信号（`ProxyApp._client_harness`）；SDK 传输写入
  `BridgeSessionState.sticky_harness`。这避免每次调用重新探测——否则 harness 会翻转、前缀会失稳。
</Note>
