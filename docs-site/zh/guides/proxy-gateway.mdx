网关是一个 aiohttp 反向代理。agent 设置 `ANTHROPIC_BASE_URL=http://127.0.0.1:7171`，零代码改动；
`POST /v1/messages` 经 TELOS 流水线后转发，其余所有路径原样透传。

## 启动网关

`telos init` 已自动在后台启动网关。你也可以手动管理：

```bash
telos gateway start                    # 后台启动（host/port/mode 取自 ~/.telos/config.json）
telos gateway start --port 7171        # 指定端口（并写回为新默认）
telos gateway status                   # 查看运行状态
telos gateway restart                  # 重启
telos gateway stop                     # 停止
telos gateway start --foreground       # 前台运行，阻塞（调试 / 容器）
```

后台启动后，状态记录在 `~/.telos/gateway.json`，日志在 `~/.telos/gateway.log`，输出：

```
TELOS gateway listening on http://127.0.0.1:7171 → https://api.anthropic.com
usage log → /Users/.../usage.jsonl
```

<Note>
  旧的 `telos proxy ...`（前台阻塞）保留为隐藏别名，参数完全兼容。
</Note>

## 默认行为

- 网关接受所有 Anthropic 协议路径；`/v1/messages` 被 TELOS 改写，其余原样透传。
- **默认非严格：** TELOS 失败时降级为透传。`--strict` 改为返回 500。
- 内嵌看板于 `/__telos/dashboard`、`/__telos/developer`、`/__telos/developer.json`。

## Harness 自动探测

网关自动判定每个请求属于哪个 harness——无需手动指定。除了主对话，Claude Code 还会通过 Haiku
发送辅助请求（会话标题生成、新话题检测）。它们没有 tools、没有 `<system-reminder>` 标签，因此网关通过 HTTP
`User-Agent` 头（`claude-cli/...`）识别它们，并**按客户端**记住结果，使辅助请求也被正确归属，不会显示为
`openclaw`。完整探测顺序见 [Harness 集成](/zh/guides/harnesses)。

## session-id 推导

代理内部，一个 LRU `_SessionRegistry`（默认上限 10000）按会话持有一个 `BridgeSessionState`。session_id
按优先级推导：

1. `x-telos-session` HTTP 头（显式覆盖），
2. `metadata.user_id`（Anthropic SDK 内建字段），
3. `blake2b(api_key + system + tools + messages[0])` → `telos-<16 hex>`。

这意味着同一对话的 N 轮（只在 `messages[]` 尾部追加）映射到**同一个** session_id，不同的初始 prompt
映射到不同的，两个不同 API key 的用户绝不撞车。

## 集成客户端

<Tabs>
  <Tab title="Claude Code">
    ```bash
    telos init --harness claude-code
    ```
    把 `ANTHROPIC_BASE_URL` 写入 `~/.claude/settings.json` 的 `env` 字段（原子写，带 `.telos.bak`
    备份与 `__telos_installed` 标记）。不碰 npm 包或 PATH，且经受住 `npm update`。
  </Tab>
  <Tab title="Codex">
    ```bash
    telos init --harness codex
    ```
    向 `~/.codex/config.toml` 添加 `model_provider = "telos"` 自定义提供方，指向
    `http://127.0.0.1:7171/upstreams/openai/v1`。Codex 默认走 OpenAI Responses API；网关将该路径作透传，
    而经同一路径的 OpenAI ChatCompletions 兼容流量会被 TELOS 处理。
  </Tab>
  <Tab title="OpenClaw / Hermes">
    通过 `telos init` 各自修补其 provider 配置以指向本地网关。
  </Tab>
  <Tab title="Generic">
    ```bash
    telos init --harness generic
    ```
    为任何尊重这些变量的客户端打印一组手动 `export ANTHROPIC_BASE_URL=...` / `OPENAI_BASE_URL=...` 指令。
  </Tab>
</Tabs>

## 撤销 / 检查

```bash
telos uninstall --harness claude-code          # 恢复安装前状态
telos init --harness claude-code --status      # 只查看，不修改文件
telos status                                   # 网关 + 各 harness 安装 + 实时流量
```
